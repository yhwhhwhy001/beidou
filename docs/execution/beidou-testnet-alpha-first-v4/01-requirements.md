# Bounded Testnet soak campaign requirements

## Authority boundary

The current authorization covers implementation and local, offline validation
only. It does not authorize clearing the durable kill switch, making a Binance
Demo/Testnet mutation, starting a real soak campaign, using Mainnet, installing
a daemon, committing, pushing, merging, or changing GitHub state.

The campaign is an `EXECUTION_PROBE`. Its fills measure execution-path
operability only and must never be represented as Alpha, profitability,
Economic Truth E0-E6, or strategy-parity evidence.

## Acceptance contract

| ID | Requirement | Local acceptance evidence |
|---|---|---|
| AC-SOAK-001 | A dedicated `apps.testnet_soak` foreground entrypoint orchestrates the existing verifier and does not implement a second exchange writer. | architecture source scan and unit tests |
| AC-SOAK-002 | The configured campaign contains 1 through 30 episodes; the approved default is exactly 30. | configuration boundary tests |
| AC-SOAK-003 | The wall-clock budget is positive and no greater than 3600 seconds; the approved default is 3600 seconds. | configuration and fake-clock tests |
| AC-SOAK-004 | Episode interval is at least 60 seconds, means scheduled start-to-start cadence, compensates for execution/reconciliation time, and performs no sleep after the final episode. | configuration and fake-clock/fake-sleep tests |
| AC-SOAK-005 | For the 2026-08-30 reauthorization, target/opening-order notional is positive and no greater than 100 USDT; the terminal runtime cap is the target, and the independent absolute account-exposure ceiling is no greater than 500 USDT. | configuration/runtime composition tests |
| AC-SOAK-006 | Maximum leverage is positive and no greater than 3x. | configuration and verifier guard tests |
| AC-SOAK-007 | Exactly one strictly validated Binance USD-M symbol is allowed for the campaign. | configuration and runtime composition tests |
| AC-SOAK-008 | Every episode that opens risk must complete a reduce-only close and end flat before another episode may start. | fake-adapter integration and reconciliation tests |
| AC-SOAK-009 | Any UNKNOWN, failed or non-completed episode, duplicate identity, close failure, residual position, position-mode mismatch, open regular/algo order, or durable unresolved trace stops the campaign immediately. | fail-closed campaign tests |
| AC-SOAK-010 | Every episode receives a unique durable namespace even when the market's last closed bar is unchanged. | identity tests and fake-adapter integration |
| AC-SOAK-011 | Probe proposals are deterministic, direction-alternating, and visibly labelled `EXECUTION_PROBE`; they are not generated by or labelled as the Alpha strategy. | kernel and trace-metadata tests |
| AC-SOAK-012 | Real network execution requires explicit `--confirm-testnet`, dedicated credentials/account identity, and a separately cleared kill switch. Missing confirmation fails before runtime construction or network access. | CLI no-side-effect tests |
| AC-SOAK-013 | The durable kill switch is engaged on normal completion, failure, cancellation, timeout, and unexpected exception. | runner cleanup tests |
| AC-SOAK-014 | A durable campaign manifest records requested bounds, per-episode outcomes, stop reason, elapsed time, trace IDs, write facts, and explicitly states `alpha_evidence=false`. | manifest tests |
| AC-SOAK-015 | No launchd, KeepAlive, daemon, automatic restart, Mainnet host, GitHub operation, or real Testnet call is part of local acceptance. | architecture scans and execution log |

## Real-campaign authorization gate

After local acceptance, the runner remains stopped and the kill switch remains
engaged. A later, explicit authorization must identify the validated working
tree, exact command/configuration, account reconciliation, credential presence
(never values), and operator-controlled kill-switch clearing procedure.
