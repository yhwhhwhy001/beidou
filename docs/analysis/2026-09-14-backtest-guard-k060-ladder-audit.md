## 第一遍 · 工程审查（均带 文件:行）

### [🔴 致命] P32c 的 q95 对「已经节流过的序列」做 bootstrap，没有在重抽路径上重放阶梯

位置：`scratchpad/p32c_rescaled_ladder.py:47-53`（`q95_of`），调用点 `:81`

问题：`q95_of(thr, ...)` 把 `thr`——节流标量在**历史顺序**上决定好的序列——切块重抽。阶梯是
路径依赖的：一条 q95 级别（−70%）的重抽路径会比历史路径（IS −39.8%）更早、更深地触发阶梯，
而 method A 把那次触发钉死在历史位置上。于是 shipped 臂的保护在它自己的 q95 里是缺席的。
docstring `:14-15` 已经指出「throttle 会改变它要控制的那条尾巴」，实现只做了一半。

复现与对照（`scratchpad/audit_p32_ladder_bootstrap.py`，block=168、draws=2000、seed 与 P32c 同）：

| universe | 臂 | A：现行方法 q95 / P(破50%) | B：路径内重放阶梯 q95 / P(破50%) |
| --- | --- | ---: | ---: |
| pit | shipped R8 | −70.8% / 57.5% | **−52.6% / 11.8%** |
| pit | rescaled R8 | −69.9% / 55.2% | −66.5% / 55.5% |
| static | shipped R8 | −69.9% / 55.8% | **−52.6% / 13.5%** |
| static | rescaled R8 | −69.9% / 55.8% | −66.7% / 55.9% |

method A 的四个数与 `scratchpad/p32c-{pit,static}.json` 逐位一致，所以差异只来自这一处方法。

后果，逐条对上冻结产物的断言：

- **C-006「采纳 k=0.60 必须同时重标 R8，否则付 16.3pp 换到更差的 q95」——方向反了。**
  在 B 下 shipped 的 q95 比 rescaled **好 14.0pp**（pit）/ **14.1pp**（static），
  P(破 −50%) 是 12% 对 55%。
- **O-2 不被 O-3 严格支配。** 真实的交换是：重标 R8 买到中位 21.3pp CAGR（q90 41.2pp，
  draws=1000 pit），代价是 P(破 −50%) 约 12% → 55%。两边都仍在已裁定的 −70% 预算内，
  所以 O-3 **可以**成立——但要以「用 43 个百分点的破位概率换 21pp 收益」的名义成立，
  不能以「q95 反而更差」的名义成立。
- **E-010 的「刀刃」（pit 触发付 16.3pp、static 不触发付 0）是 method A 的产物。** 在 B 下
  两个 universe 给出几乎相同的数（−52.6% 对 −52.6%），刀刃消失。
- 16.3pp 是单条历史路径的样本内数；B 的中位是 21.3pp，历史路径偏轻。

修复方向：`q95_of` 接受未节流的 `net` 与 policy，在每条 draw 上先 `replay_ladder` 再算 MDD。
遗留偏差两臂共担且已记：A-003 的周块 bootstrap 破坏多月 regime 结构（所有 q95 偏乐观），
以及 P32b 的近似（标量乘在已实现净值上而非重推权重路径）。

### [🟠 高危] `liquidation_touches` / `min_margin_buffer` 是恒等式，不是测量

位置：`beidou_alpha/backtest.py:368-370`

问题：`buffers[t] = (1 + realised - charge) / (gross * maintenance_margin_rate)`，而
`gross ≤ max_gross = 2.0`（`config/live.demo.yaml:173`）、`maintenance_margin_rate = 0.005`
（`backtest.py:236` 默认）。于是 buffer ≥ 100 × (1 + r − c)：**要触到 1.0，需要单根 1h bar
亏掉约 99%。** 全网格 `liquidation_touches = 0`、`min_margin_buffer ≥ 94.75` 不是关于爆仓
风险的证据，它是 `max_gross` 与 mmr 的算术。

※ 作者已披露结论本身（提交信息「限制的不是爆仓只是回撤」、C-004），**不降级**：问题不在
结论，在于 C-004 把一个恒等式列为 P1 SUPPORTED 的证据，并在 k 的每一档重复它，读起来像
「跨 k 复核过的安全裕度」。真正的爆仓通道是 RISK-2：权益 52.65% 是 BTC 抵押品，回测建模的
抵押品是零，且它随 k 同步放大——那条通道这套仪器看不见。

修复方向：要么把这两个字段标注为「结构上不可达，仅作不变式检查」，要么换成能动的量
（`min_liq_distance` 已在实盘 cycle 里）。

| N | 242（今天） | 280 | 300 | 350 | 484 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 门 | 1.5493 | 1.5662 | 1.5741 | 1.5918 | 1.6282 |
| 余量 | +0.0426 | +0.0257 | +0.0178 | +0.0001 | −0.0363 |

## 两把尺子，代码里的出处

`beidou_live/risk_budget.py:223` `attributed_drawdown_state`：
`path = base + cumsum(attributed)`，`attributed` 只累计 income 行（已实现 P&L、资金费、手续费），
**不含未实现盈亏**；`base` 是账户**总权益**（今天 52.65% 是 BTC 抵押品）；path 是线性的，不复利。
P32b/P32c 以及正文第一轮的重放读的是书的**盯市净值**——每一根不利 bar 当场计入。

一本持有浮亏的动量书，两把尺子必然分叉。分叉多少（k=0.60，2021-01→2026-09）：

| | pit | static |
| --- | ---: | ---: |
| 盯市最深回撤 | −39.85% | −35.29% |

## 本轮自身的限制
