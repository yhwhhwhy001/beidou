### K-4 为什么不读 `running` 臂

`running` 是现行档位 ((−0.49, 0.45), (−0.70, 0.30))。目标是绝对值，`rung_scalar` 把它换成乘数 min(1, 目标 / k)：

| k | `running` 的两档乘数 | 规则在这个 k 上的两档乘数 |
|---|---|---|
| 0.60 | 0.75 / 0.50 | 0.75 / 0.50 |
| 0.50 | 0.90 / 0.60 | 0.75 / 0.50 |
| 0.45 | 1.00（恰好 1）/ 0.67 | 0.75 / 0.50 |
| 0.40 | 1.00（钳住）/ 0.75 | 0.75 / 0.50 |
| 0.35 | 1.00（钳住）/ 0.86 | 0.75 / 0.50 |
| 0.30 | 1.00（钳住）/ 1.00（恰好 1） | 0.75 / 0.50 |
| 0.25 | 1.00（钳住）/ 1.00（钳住） | 0.75 / 0.50 |
| 0.20 | 1.00（钳住）/ 1.00（钳住） | 0.75 / 0.50 |

乘数到 1 就不减仓：k ≤ 0.45 时第一档失效，k ≤ 0.30 时两档都失效，0.25 与 0.20 上的 `running` 就等于无梯。
那是把为 0.60 校准的档位留在更小的 k 上，不是 D-035 的规则在这个 k 上的样子。
所以 K-4 读 `ladder@k` 臂，档位由因子 1.0 推出。它和 p32h 的 `ladder@k` 是同一种臂，k 与 block 起点都是已有的。
k = 0.60 时两者是同一把梯，档位只差浮点噪声（−0.48999999999999994 对 −0.49）。实测两漂移 × 两 universe 共四组读数逐位相同。

## 7. 拿不准的地方

- **诚实漂移只挪了均值。** 1.2306 是 tsmom 单书的样本外读数，pit、16 格、k = 0.60。这里的序列是主书加 flow `sleeve` 两本书，static 也套了同一个数，这两点都没单独量过。1.2306 自身的抽样标准误约 0.44（由报告的 `oos_selection.variance` 算出），95% 区间大约 0.36–2.10。这个区间比原漂移与诚实漂移之间的差（Sharpe 约 1.70 对 1.23）还宽。
- **0.20 以下没有量。** 诚实漂移下规则要的 k 在 0.20 以下，要定具体值就得加新格子，那是新的 prior-trials 申报。插值：pit k≈0.200，static 网格内没有跨越。
- **headroom 不到 1pp 的格子读作「在线上」，不读作「守得住」。** 诚实漂移的 pit 0.20 与等比例打折的 static 0.20 都是这种格子；原漂移 static 0.25 的 q95 区间下沿离线只剩 0.29pp。
- **换算因子会漂。** 1.7479 自 09-23T05:00Z 起没变过，因为两个峰值都没刷新。书一赚钱，USDT 占比上升，因子下降，同一个 k 的可动用读数变浅；反过来会变深。写成常数的档位会慢慢偏离 USDT 预算。
- **档位取两位小数（−0.28 / −0.40）没有量。** 它比精确值早 0.03 / 0.05pp 刹车，方向偏保守，量级不影响结论。
- **K-4 是推理。** 它假设换完之后可动用恰好等于总权益，书的大小不变。回测本来就不建模抵押品，所以 K-4 反而是回测描述得最直接的账户。换抵押品这笔交易本身（时机、费用）没有评估，那是操作者的决定。它回答预算，不回答 D-041：k = 0.60 下 tsmom 的证据仍是 FAIL。
- **p32f 的三条误差仍然成立，方向都指向真实尾部更差。** 周块 bootstrap 抹掉多月 regime；可动用换算假设亏损全落在 USDT，BTC 与书同跌时会低估（K-4 没有这一条）；CAGR 的绝对水平只有差值有意义。
- **q95 只是历史的周块重抽，不是预测。** 规则读的是点估计。
