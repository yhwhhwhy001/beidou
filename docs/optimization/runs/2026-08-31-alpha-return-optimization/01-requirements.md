# Requirements

| ID | Requirement | Acceptance signal |
|---|---|---|
| ARO-DATA-001 | Every newly written K-line manifest binds schema version, venue, exact endpoint, source class, retrieval time, environment, intended use, event-time range, row count, and content hash. | Unit tests inspect the persisted JSON fields and deterministic hash. |
| ARO-DATA-002 | Binance Demo/Testnet and unknown sources are always classified `EXECUTION_ONLY` and cannot pass economic-research eligibility. | Exact-host tests reject Demo, Testnet, unknown, and hostname lookalikes. |
| ARO-DATA-003 | Existing data with a legacy/missing manifest cannot be appended and relabelled as a new trusted source. | Backfill rejects before parquet mutation and reports a typed reason. |
| ARO-DATA-004 | Economic eligibility verifies manifest bytes/metadata, closed ordered bars, interval continuity, finite/legal OHLCV, anomaly coverage, and cross-source reconciliation. | Clean trusted fixture passes; tampering, gaps, unclosed bars, extreme unreconciled jumps, and weak cross-source checks fail. |
| ARO-DATA-005 | Factor mining from local storage uses the persisted manifest and fails closed when it is missing, legacy, mismatched, Demo/Testnet, or otherwise ineligible. | Worker tests fail before `MiningRunner` construction for untrusted data. |
| ARO-DATA-006 | E0 Economic Truth cannot pass without a bound `PASS` market-data assessment for an eligible source and manifest hash. | Economic-truth tests reject Demo/legacy/malformed assessment evidence. |
| ARO-DATA-007 | Existing execution behavior and existing user modifications remain untouched; no network trading actions occur. | Scoped diff plus regression tests; authority remains local-only. |
| ARO-ALPHA-001 | No alpha parameter/candidate may be selected until ARO-DATA-001..006 pass on a newly acquired trustworthy frozen dataset. | No selection occurs before admission; any later fixed-policy diagnostic remains non-promotable without the downstream economic gates. |
| ARO-DATA-008 | The authorized August dataset is isolated, exact-scope, checksum-bound, and reconciled row-for-row between the official archive and the unauthenticated public K-line API. | 120 official daily checksums pass; each symbol has 720 closed ordered bars; raw fields agree 720/720 with maximum close deviation at most 5 bps. |
| ARO-ALPHA-002 | The shipped Alpha baseline is evaluated causally without parameter search or candidate selection, using closed bar `t`, next-bar-open execution, a versioned explicit diagnostic cost schedule, and a reproducible report. | Timing audit reports zero lookahead/same-bar executions; repeat report hash is stable; benchmark and turnover are independently recomputed. |
| ARO-ALPHA-003 | No Alpha change or profitability claim may be promoted from the observed August range without complete PIT/feature lineage, named Metric Owner policy, stateful `NO_ACTION`/target semantics, fill-calibrated costs, impact/capacity, and a pre-sealed unseen evaluation. | State remains `DIAGNOSTIC_ONLY / DO_NOT_PROMOTE`; Paper/Testnet remain `HOLD`; Mainnet remains `PROHIBITED`. |
| ARO-ALPHA-004 | Add an additive stateful Alpha evaluation contract. A caller must supply a strategy/instrument/venue-bound current-position snapshot and a scope-bound cost snapshot whose fact time is not after the decision and whose validity window includes the decision. | Missing, blank-scope, naive-time, future, expired, non-finite, scope-mismatched, or non-canonical source-bound inputs fail with a stable typed error code before a target is returned. The forecast provider must return the exact strategy/instrument/venue/decision time. |
| ARO-ALPHA-005 | `NO_ACTION` means preserve the current verified strategy-sleeve weight; `BUY` and `SELL` mean use the forecast raw score. No other forecast side is inferred by the v2 contract. | Contract tests force a sub-threshold nonzero forecast and prove that its stateful target equals the supplied current weight; directional cases equal the raw score; unsupported sides fail closed. |
| ARO-ALPHA-006 | Costs are explicit caller inputs rather than dataset-derived or hard-coded facts. Fee and slippage are finite/non-negative, funding is finite, and all scope, validity, values, schema version, and the canonical nonzero source-artifact SHA-256 are covered by a recomputable snapshot binding digest. | The forecast exactly preserves the injected values/source, passes its cost arithmetic invariant, and the result carries the snapshot binding; changing values under the same source digest changes the binding. Missing, malformed, zero, future, expired, non-finite, or mismatched inputs fail. |
| ARO-ALPHA-007 | The stateful result exposes normalized side/semantic, decision time, fact/expiry times, source digests, and canonical snapshot binding digests. The existing `evaluate()` path remains behavior-compatible and is machine-labelled legacy diagnostic-only. | Existing offline/baseline callers continue to pass unchanged; v2 can be independently recomputed. Cost changes do not alter the pure market feature hash. |
| ARO-ALPHA-008 | Treat an injected forecast provider as untrusted. V2 accepts only exact scope/time bindings, finite raw score in `[-1, 1]`, positive BUY, negative SELL, and verifiable exact cost arithmetic/source binding. | Adversarial provider tests reject scope, timestamp, direction, range, cost arithmetic, and cost-source mismatches with stable typed codes before returning a target. |
| ARO-OOS-001 | Add a versioned, domain-separated canonical pre-seal package for window custody and candidate freeze, and transitively bind its digest through `ExperimentRunIdentity` into governed v2 seal, access receipt, and promotion decision. | Every custody/candidate/identity/seal field has an explicit mapping and single-field mutation test. Missing or changed readiness evidence prevents v2 seal, receipt, and promotion. |
| ARO-OOS-002 | Do not invent an unseen window, Metric Owner, economic threshold, custodian, or source commitment. Until all are supplied, the active run remains `DRAFT_BLOCKED`; v1 objects/decisions are machine-labelled `LEGACY_RESEARCH_ONLY / NOT_ELIGIBLE_FOR_V2_PROMOTION`. | The current assessment lists missing reasons and no real OOS seal/read occurs. Direct legacy calls cannot yield a decision marked v2-eligible. |
| ARO-OOS-003 | The one-time OOS access grant must be process-safe and committed before any receipt can unlock data. Concurrent callers, stale lock holders, crashes, and partial audit state fail closed without issuing two valid receipts. | Multi-process tests prove exactly one successful receipt; lock-owner death releases safely; committed/partial audit state prevents a second grant and remains independently detectable. |

## Authorized contract slice

- Required now: additive stateful target/cost contracts, adversarial provider validation, audit bindings, legacy compatibility, governed OOS v2 preseal/seal/access/promotion isolation, and atomic one-time access.
- Explicitly excluded: Alpha parameter changes, candidate search, August re-optimization, a real forward-window choice, economic thresholds, Paper/Testnet/Mainnet activation, commit, push, deployment, restart, account/order access, or money movement.
- A canonical SHA-256 digest proves deterministic binding and tamper detection inside this interface. Authenticity and custody of the referenced source remain producer/gate responsibilities and are not inferred from digest shape alone.
