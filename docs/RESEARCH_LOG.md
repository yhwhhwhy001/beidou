## 2026-09-03 · 第一轮：小时级信号诊断（mainnet 公共数据 2021-06 → 2026-09）

方法：`beidou research diagnose`（按前瞻期计算时序 IC 与横截面 IC，Newey-West t 统计；不做组合构建的等名义信号回测）与 `beidou research validate`（purged walk-forward + CPCV + DSR/PBO + 成本压力）。成本 7 bps 换手 + 实际资金费率。

### 结论

1. **旧系统的 TrendAlpha（5/20/50 小时动量）没有 edge。** 2021-06→2026-09 四币：信号本身毛收益 ≈ 0，1h/4h 前瞻 IC 显著为负（NW t = −6.3 / −3.5），validate 判定 FAIL（OOS Sharpe 0.32，DSR p 0.83，fold 一致性 0.40）。2026-08 的 +2.4% 是上涨月的运气；且旧评估还带着换手率 bug（E-022）。
2. **小时级 1–24h 是反转效应**：tsmom / xsmom / residual 在短前瞻期 IC 全部显著为负；meanrev 在 1h/4h IC 显著为正（t = 6.8 / 3.8）——但 meanrev 的等名义回测亏损（尾部趋势延续时持仓亏大钱），需要时间止损与更强趋势门。
3. **多日/周级横截面效应为正**：
   - flow（taker 主动买卖比，横截面去均值）24–168h 横截面 IC = 0.023–0.056，t ≈ 5–6，是所有信号里最强的预测力；信号本身零成本 Sharpe 0.74，但换手 477 单位 → 需要更长窗口 + 相对再平衡带。
   - tsmom 周级（168/336/720h）：信号本身零成本 +95.7%、Sharpe 0.91；**扣全成本仍 +60.2%、Sharpe 0.66**（成本占比 27%）。首个扣费后为正的候选。
   - xsmom（24/72/168h）零成本 Sharpe 1.09 但成本吃掉 99%；residual 零成本 +120% 但成本吃掉 94% → 都需要更长周期。
4. **换手成本是主要敌人，而且大头来自组合构建而非信号**：逐 bar 波动率缩放让权重每根 bar 微调（tsmom 四币换手 1150 单位 vs 信号翻转 2926 次）。已加入相对再平衡带（同向调仓 < 25% 不动）与新币最短历史过滤（720 根 bar）。
5. carry：横截面 IC 在所有前瞻期显著为正（t ≈ 4–5），但等名义回测亏损——极端资金费率的币（meme）价格波动幅度吞掉排序上的正确性；作为横截面倾斜 + 波动率缩放再评估。

### 下一步

- 对 tsmom（含周级 horizon 集）、flow、xsmom、residual 用完整组合管线 validate；通过者写入 `config/alpha_registry.yaml` 的 evidence 后启用。
- meanrev 加最长持有期与更强趋势门；carry 改为横截面倾斜。
- 实盘：demo 账户 24h 跑通后，用 `beidou report daily` 的按策略归因对照回测预期。

## 2026-09-03 · 第四轮：xsmom / carry 的硬化与否定，以及两处验证工具的诚实性修正

目标是让 xsmom 与 carry 通过验证；方法是先修**经济逻辑上**的缺陷，再诚实验证。结论：**两者作为独立策略都没有通过**，但过程产出了三个可复用的发现和两处工具修正。累计试验数（DSR 分母）：tsmom 45、xsmom 26、flow 28、residual 8、carry 5。

### xsmom

| 第三轮（raw、不跳过、周级） | — | 0.72 | 0.70 / −0.01 | 0.12（4 试验；按累计 26 试验会更差） | 0.05 | FAIL |

机制：**风险调整后的信号与组合层的波动率目标是双重惩罚**——每个币先按自身波动率归一化信号，再按波动率缩放权重，结果是一本几乎等风险、等信心的平书，恰好抹掉了动量最依赖的高波动赢家。这是一条通用教训：信号层与组合层只能有一处做风险归一化。

最终判决来自 3 策略相关性（`research correlate --strategies tsmom,flow,xsmom`）：xsmom 单独 Sharpe 0.70，与 tsmom/flow 相关 0.21/0.26，加入等权组合后 Sharpe **1.80 → 1.66（边际 −0.14）**。即使作为分散化工具也不成立。xsmom 保持禁用，registry 里保留其最佳诚实配置。

carry 唯一说得通的角色是**拥挤度过滤**：tsmom 在某币上做多、而该币的资金费率又处于横截面极端高位时，多头已经拥挤，把信号缩一半。实现为 `tsmom` 的 `crowding_window/cut/penalty` 参数（默认关闭）。对照实验（penalty 0 vs 0.5，其余参数固定）见下一条。

### 两处工具修正（都在结果出来之后才发现，如实记录）

1. **PBO 在网格 <4 时不再作为硬门禁。** CSCV 需要对多个策略排名；只有 2 个配置时 PBO 退化为"两者在多少子区间里互换名次"，0.67 只说明改进量小于子区间噪声，不说明过拟合。改为仅供参考（`min_trials_for_pbo=4`），并在报告中保留数值。
2. **跨轮次试验账本** `reports/research/trials.jsonl`。之前 DSR 只按当轮网格计分母，缩小网格就能"通过"。现在每次 validate 追加每个配置的全样本 Sharpe，下一次自动把同策略的历史试验计入 DSR 分母并用其离散度做方差；账本之前的轮次用 `--prior-trials` 手工申报（上表数字）。

### flow：把负折查清楚

**先修正一个方法论问题。** 报告里的"负折"编号依赖折边界：同一条净值序列在 `min_train` 取 4000/5000/6000 时，负折分别落在第 4 折 / 第 4 折 / 消失（各折 Sharpe [0.63, 1.40, 1.33, −0.61, 2.65] → [0.76, 1.20, 1.16, −0.22, 2.47] → [0.85, 1.74, 0.09, 0.56, 2.12]）。06:27Z 报告的折向量按已知参数无法复现（全样本 Sharpe 1.1582 完全复现，折向量不能——当时的网格未被记录），所以本轮按**日历窗口**定位亏损段，并把这条教训写进工具：折数不是证据，日历窗口才是。

**亏损段 = 2024-10 → 2025-09，亏损几乎全在 2024-11（单月 −8.6%，该折 −9.8%）。** 分解：

| 项 | 数值 |
| --- | --- |
| 多头腿 | +21.2%（Sharpe 1.10） |
| **空头腿** | **−28.0%（Sharpe −1.08）** |
| 最大亏损币 | XRP 空头 −11.0%、ADA −8.9%、SUI −8.5% |

### legacy 的三个模块：只有纪律可移植，没有数值可移植

三份只读审计（tag `v2-governance-final`）的结论，细节见分析文档 E-032 ～ E-035：

- **止盈止损**：交易所原生条件单，止损 = ATR% × 2.0 × 波动率档位 × 点差因子，止盈 = 风险 × RR（2.0 × 9 个手调因子）。没有任何回测证明它有正贡献，且阈值是在错误的 RSI/ATR 数学上校准的（当时的 P0 R-M03-1）。软件侧的 `TrailingExit`（并不从高水位算）与 `TimeExit`（入场时间未持久化，每次重启归零）从未执行。事故统计：仓位无保护时长 p99 1,329s、最大 5,078s。
- **交易池**：5 维打分（点差/深度/成交量/稳定性/容量）+ 24h 观察期 + 隔离状态机，三套互不一致的实现；成交量分恒为 0 导致**任何币都无法激活**；隔离 = 冻结，被隔离币的仓位既收不到入场也收不到退出信号。时点快照机器从未接进回测。
- **自适应 sizing**："canonical" 引擎是可用保证金比例 × 八个标量之积，从未验证（回撤输入硬编码 0；唯一一次 soak 因 MIN_NOTIONAL 在 3 秒内零成交死亡）；实际交易路径 1% × 2% 双重叠加 → 名义恒 ≈ 10 USDT；交易所杠杆从未同步（模型按 3x 算，交易所停在 20x）。

移植的纪律：缺特征就不交易而不是编默认值；min-notional 拒绝而不放大 + ROUND_DOWN；退出侧遍历仓位而不遍历池子；只有交易所的 ACK 才算数；一个风险预算。

## 判定规则修订（D-020，2026-09-04；先登记，后执行）

**背景。** 第六轮发现 tsmom 的 registry 配置（拥挤度关闭）与其证据（拥挤度 0.5 的 133239Z）不一致；随后的三次重验（时点 16 点网格、时点两点对照、静态 16 点网格）除 DSR 外全部通过，DSR p 分别为 0.40 / 0.32 / 0.33。原因不在策略，在尺子：133239Z 的 p 0.0002 来自账本里只有近似相同配置时接近 0 的合并方差；今天账本里 40 条 tsmom 试验混入了旧的小时级 horizon（Sharpe ≈ 0），合并方差把 50 次试验的零假设最大 Sharpe 抬到约 1.5，全样本 1.64～1.72 的候选永远不"显著"。DSR 在两个方向上都失真了。

**操作者决定（2026-09-04，对应五个选项中的第 4 项）。** 判定改为以样本外为主，对所有策略统一，先写入本段再改代码：

| 项 | 规则 |
| --- | --- |
| PASS | 走前 OOS Sharpe ≥ 1.0 **且** OOS 净收益序列的 Newey-West t ≥ 2.0 |
| WEAK_PASS | OOS Sharpe ≥ 0.5 且 t ≥ 1.5 |
| 硬门（任一不满足即 FAIL） | 折一致性 ≥ 0.6；CPCV 负路径比例 ≤ 10%；PBO ≤ 0.30（网格 ≥ 4 时）；成本 2× Sharpe ≥ 0 |
| DSR | 每份报告照常输出（合并方差；第七轮将并列输出家族方差口径），**不再一票否决** |

理由：DSR 惩罚的是**样本内** Sharpe 的选择偏差；走前验证已经把参数选择放在训练段里做，OOS 序列的显著性是更干净的检验。跨轮的"家族选择"（试过哪些网格、哪些救援）仍由账本计数暴露，并配合预登记与探针书（D-019）控制。t 统计量用 HAC 方差（`metrics.newey_west_tstat`），对小时级收益的自相关与波动率聚集做了修正；5 年 OOS 下 t ≥ 2 大致等价于 OOS Sharpe ≥ 0.9，样本更短时要求更高。

**规则的两处局限（第七轮会话提出，本会话独立复算证实；`scratchpad/verify_d020.py`）。**

1. **两个 PASS 条件在长窗口上并不独立。** 小时级净收益几乎无自相关，HAC 修正只有 0.1%～0.4%：181803Z 上 t = 3.5027 而 Sharpe × √年数 = 3.5005（比值 1.0006），拥挤度关闭臂 3.7333 对 3.7282。因此 t ≥ 2 在 5.14 年窗口上等价于 Sharpe ≥ 0.88，**比并列的 Sharpe ≥ 1.0 更松**；t 门只在 OOS 窗口短于 4 年时才真正起作用（t = 2 与 S = 1 在 4.0 年处相等）。这不改变 tsmom 的判定（1.54 / 3.50 两项都远超），但不能把 D-020 说成"两个独立条件"——它是一个 Sharpe 门加一个**短样本保护**。下一轮需要补一个真正对选择敏感的条件（按 horizon 家族分组的 DSR，或最差折 Sharpe 下限）。
2. **报告头条的 OOS 是"逐折择优"的混合口径。** 181803Z 每折选中的 `crowding_window` 是 [72, 0, 72, 72, 0]，其中三折跑的是 registry **不运行**的拥挤度修正。独立复算：registry 实际配置（拥挤度关闭）单独的走前 OOS Sharpe **1.6450**、t **3.7333**、各折 [1.47, 0.49, 2.24, 1.71, 2.31] 全正；开启臂 1.5291 / 3.4798；混合 1.5445 / 3.5027。方向是保守的（实际运行的臂更好），`best_params` 也仍等于 registry 参数，所以证据门有效；但读报告时不要把 1.54 当成实盘配置的成绩。

**对现有 registry 的影响。** tsmom 用"拥挤度关闭 vs 开启"的两点对照（与 175236Z 同一实验，registry 参数 `crowding_window: 0` 即对照臂）在时点 universe 上重验，按新规则判定后更新证据指针；flow 只做空本轮**不**重验，仍以探针书身份运行（它在新规则下也可能达到 t ≥ 2，但它的跨轮选择次数最多，样本外证据只能由实盘产生）。实现：`beidou_alpha/validation/walk_forward.py`（`oos_t_stat` / `oos_t_lags` / `oos_bars`）、`beidou_alpha/validation/verdict.py`。

### 第六轮补充（round 6b，2026-09-04）：把 KILL-027 的机制关掉，并给实盘装上可复现性监控

第六轮修的是 KILL-027 的**实例**（拥挤度修正被静默跳过）；本次修的是**机制**——让"实盘跑了没被验证的配置"这件事无法再悄悄发生。

- **信号声明自己的输入需求。** `SignalSpec.needs_funding(params)`：tsmom 只在拥挤度修正真正打开时（window > 0 且 penalty > 0）声明，carry 恒为真。声明为真而没拿到资金费率历史时，`AlphaModel.targets` 直接报错；行情端口不提供 `funding_history` 时 `LiveEngine.startup` 拒绝启动。也就是说，把 `crowding_window` 改回 72 现在要么正确运行、要么明确失败，不会再有第三种结果。
- **实盘面板 == 研究面板。** 新增 `MarketData.funding_history(symbols, start_ms)`，取与 K 线同一窗口的结算费率，由 `Panel.from_frames` 按 bar 对齐——与研究侧 `load_panel` 完全相同的语义。测试直接断言：拥挤度打开的配置下，实盘路径与研究路径的逐策略目标**逐位相等**，且该 panel 上修正确实在起作用（否则这个相等没有意义）。
- **一个地方构造周期输入。** `beidou_live/inputs.py` 被引擎和验证器共用，离线复现不会与它所复现的周期发生实现漂移。资金费率历史只在模型需要时才取（额外请求数为 0，除非有信号声明）。
- **M-011 `beidou live verify`。** 用公共数据 + `state.json` 离线重算上一周期的 contributions 并逐币比对。contributions 必须相等；targets 的差异只是提示（退出层 / 节流 / 护栏在模型之后动作）。**对运行中的循环实测（bar 2026-09-04T01:00Z）：tsmom 与 flow_short 两本书的最大差异均为 0.0**，1,442 根 bar、15 个币。这是第一条"实盘输出可被独立复现"的证据。

## 2026-09-04 · 第七轮补充：H-001（`conviction_mode: sign`）按预登记规则执行

三条检查全部通过 → 规则判 **ADOPT**。但把"通过"当成"更好"是不诚实的，配对检验说得更清楚：

- 两条净值 OOS 相关 **0.966**；逐 bar 收益差的 Newey-West **t = −0.047，p = 0.963**。年化收益差 −0.0009。**幅度不携带任何收益信息**，这是本节真正的结论，比 Sharpe 的 −0.04 更值得记住。

- 那为什么收益相同、成本更低，Sharpe 却略低？因为 `sign` 把每个可执行仓位放到满仓，平均敞口从 0.383 升到 0.445，波动率目标之后仍留下略高的实现波动。它买到的是更低的换手与更浅的回撤，付出的是略粗的仓位粒度。

**两个操作性发现（本节的副产品）：**

1. `research validate` 的 `best_params` 按**全样本 Sharpe**选，所以一个按预登记规则胜出、但全样本 Sharpe 略低的候选永远不会成为网格报告的 `best_params`。配合已上线的"registry 参数必须等于报告 `best_params`"启动门（D-023），采用这类候选**必须**另出一份单配置报告——这正是 020459Z 的用途。若以后这种情况变多，应让 `validate` 支持按预登记规则而不是全样本 Sharpe 选 best。

## 判定规则补门（D-028，2026-09-04；先登记，后实现，后评估）

KILL-045 指出 D-020 的两个 PASS 条件不独立：小时级净收益上 NW t 与 `Sharpe × √年数` 的比值是 1.001，所以在五年窗口上 `t ≥ 2.0` 等价于 `Sharpe ≥ 0.88`，比并列的 `Sharpe ≥ 1.0` 更松。D-020 因此实际只有一道门，而且**没有任何条件对「这个策略跨轮次被试过多少个配置」敏感**——走前 OOS 只内嵌了折内选择。

**新增第二条件（本节写完之后才实现、才计算结果）**：

> PASS 还要求 `oos_sharpe ≥ E[max OOS Sharpe | 零假设]`。零假设取**单个 OOS Sharpe 估计的抽样分布**（Bailey & López de Prado 的方差 `(1 − γ₃·SR + (γ₄−1)/4·SR²)/(n−1)`，按 OOS bar 数），而**不是**账本的合并离散度——后者在两个方向上都退化过（近重复试验时接近零，混入异质配置时被抬高），这正是第七轮的起点。试验数取该策略账本里**去重后的配置数**加上申报的先验数。
>
> 这样做的理由：DSR 原本削减的是**样本内** Sharpe，而走前已经处理了折内选择；真正没人管的是**跨轮的家族级选择**。把同样的削减施加在**样本外**序列上，恰好只惩罚这一件事。阈值是推导出来的，不是调出来的。
>
> `oos_t_stat` 条件保留，但降格为它实际的作用：**短样本保护**。四年以内的 OOS 窗口上它比 Sharpe 门更严，四年以上不约束。文档不再把它称作独立的第二道门。

WEAK_PASS 沿用同样结构，试验数相同、阈值相同，只是 `oos_sharpe` 与 `oos_t_stat` 用 0.5 / 1.5 的下限。DSR 仍然只报告不否决（D-020 不变）。
