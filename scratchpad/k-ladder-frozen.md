## 7. Phase 7 审查结果（2026-09-14，追加；上文 E-010 / C-006 / Options 表一字未改）

审查者 beidou-7a，独立 backtest-guard，报告在
`docs/analysis/2026-09-14-backtest-guard-k060-ladder-audit.md`，脚本
`scratchpad/p32d_ladder_bootstrap_pathwise.py`（取代 `p32c.q95_of`）与
`scratchpad/p32e_ruler_divergence.py`。上文保持冻结态，因为不那样就说不清审的是哪一版。

**K-04（第一步，已由 `4a8cfd18` 写进记录）。** `p32c.q95_of` 对**已节流**序列做 block
bootstrap。阶梯路径依赖，重抽路径比历史路径深得多，而 method A 把触发钉死在历史位置。在
draw 内重放后 shipped 的 q95 从 −70.8% 变 −52.6%，**C-006 的方向反了**，E-010 的「刀刃」
是方法产物。

**K-05（第二步，本节新增，它把 K-04 的结论也一起限定住）。** K-04 的两条臂都用**盯市净值**
当阶梯的 ruler，而 R8 不读那个。`beidou_live/risk_budget.py:223` 的
`attributed_drawdown_state` 读 `base + cumsum(attributed)`：只累计 income 行（已实现 + 资金费
+ 手续费），**不含未实现盈亏**，而且 `base` 是含抵押品的账户总权益。E-015 把它记成「限制，
净效应未量化」——量出来是这样（k=0.60，全历史，`p32e`）：

| | pit | static |
| --- | ---: | ---: |
| 盯市最深回撤 | −39.85% | −35.29% |

| 越过第一档（−35%）的 bar：盯市 | 785 | 1 |
| 越过第一档的 bar：**已实现 ruler** | **0** | **0** |

**五年七个月里，R8 按它真正读的那把尺子一次都没有触发过。** 实盘记录同向：108 个同时带两个

**三条要写下来的话。**

1. **O-2 与 O-3 在实盘里几乎是同一个决定。** 按真实 ruler，两者的 q95 差 0.6pp、P(破50%)
   差约 1pp、CAGR 代价都是 0.0pp。O-3 表里那 16.3pp / 21.3pp 的「价钱」和 K-04 给 shipped 记
   的 14pp 尾部好处，**都是盯市 ruler 下的量，不是实盘会发生的事**。C-006 撤回之后不应换成
   「所以 shipped 更好」——正确的结论是这个选项差异本身很小。
2. **真正的发现是：k=0.60 下这个账户基本没有回撤刹车，两个选项都一样。** 不是「阶梯该不该
   重标」，是「阶梯按它自己的尺子够不到」。q95 −69.3% / −69.9% 贴着已裁定的 −70% 预算，
   余量 0.1–0.7pp，而 A-003 说这些 q95 **偏乐观**（周块 bootstrap 破坏多月 regime 结构）。
3. **要修的是 ruler，不是档位。** 在 ruler 对齐之前改 `policy.py:173` 的数字，改的是一个不
   生效的东西。三条候选，未定价，留给操作者：让 R8 读含未实现盈亏的书级净值；或把档位按
   已实现口径重标（−35% 的已实现相当于盯市约 −70%）；或承认它是事后记录而不是刹车，另建
   一个真的刹车。

**C-004 同时更正**（审查的另一条，已由 `4a8cfd18` 接受）：`liquidation_touches = 0` 与
`min_margin_buffer ≥ 94.75` 是 `max_gross ≤ 2.0` 与 mmr 0.005 的恒等式——buffer ≥ 约 100×，
碰到 1.0 需要单根 bar 亏约 99%。结论（限制的是回撤不是爆仓）成立，作为 P1 SUPPORTED 的**证据**
不成立。真能强平这个账户的是抵押品重定价（RISK-2），而这套仪器看不见它。
